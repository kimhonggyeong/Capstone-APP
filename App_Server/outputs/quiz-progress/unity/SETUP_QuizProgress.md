# 앱 퀴즈 누적 학습 진행도

`FinanceQuizManager`는 정답 확인마다 문제 ID와 정답 여부를 저장합니다.
같은 문제를 다시 풀면 누적 풀이·정답 횟수에는 반영되고, 푼 문제 수와 진행률은 중복 증가하지 않습니다.
퀴즈 한 회차를 끝까지 완료하면 완료 세션 1회를 기록합니다. 오답 5개로 중단한 회차는 완료로 기록하지 않습니다.
웹의 완료 주제는 같은 용어의 세 문제 ID가 모두 모였을 때 웹에서 계산합니다.

## Unity 연결

1. 누적 학습 진행도를 표시할 패널 또는 빈 오브젝트에 `QuizLearningProgressUI`를 붙입니다.
2. `Progress Text`에 퍼센트를 표시할 TMP 텍스트를 넣습니다.
3. `Progress Slider`에 학습 진행도 슬라이더를 넣습니다.

퀴즈 씬, 마이페이지 등 여러 씬에서 사용할 수 있습니다.
텍스트와 슬라이더는 직접 연결하며, 슬라이더 범위 0~100은 코드에서 설정합니다.
퍼센트는 소수점 없이 반올림한 정수(예: 25%)로 표시합니다.
기존 `FinanceQuizManager`의 `Progress UI`는 현재 퀴즈 회차의 문제 순서 표시이므로 그대로 둡니다.
같은 텍스트/슬라이더를 두 컴포넌트에 중복 연결하지 마세요.

## 서버와 계정

`ServerConfig`의 주소와 `AuthManager.Instance.Username`을 사용합니다.
별도로 서버 주소나 사용자 ID를 입력하지 않습니다. 웹의 사용자 키도 username이어야 기록이 합쳐집니다.
서버 주소는 `Full_Server`를 실행한 PC의 주소로 설정합니다. 통합 서버는 수정 후 재시작해야 합니다.

- 조회: `GET /api/users/{username}/quiz-progress?total_quiz_count=360`
- 저장: `POST /api/users/{username}/quiz-progress/events`
- 컬렉션: `anttitude_scenario.quiz_progress` (실제 DB 이름은 서버의 MONGODB_DATABASE 설정)

웹도 통합 서버의 같은 API를 사용하면 저장을 한 곳에서 처리합니다.
웹이 별도 Python 서버를 사용한다면 같은 MongoDB와 DB 이름을 사용해야 하며,
기존 웹 서버의 읽기 후 전체 문서 교체 저장 방식은 동시 저장을 덮어쓸 수 있으므로
가능하면 웹의 SCENARIO_SERVICE_URL도 통합 서버를 가리키도록 설정합니다.
브라우저가 열린 채로 있으면 웹의 재조회 또는 새로고침 시 앱 기록이 표시됩니다.

## 통신 실패

진행률에는 기기에 임시 저장된 미전송 풀이도 반영합니다.
전송 실패 시 사용자별 PlayerPrefs에 보관하고 10초 간격으로 다시 전송합니다.
같은 전송 ID의 재시도는 서버에서 한 번만 집계합니다.
웹에는 서버 저장이 성공한 기록부터 나타납니다.
씬 이동은 전송을 중단하지 않으며, 로그아웃 뒤 다른 계정에 이전 기록을 섞지 않습니다.
앱의 진행도 패널이 켜져 있는 동안은 기본 15초마다 웹의 새 기록도 다시 조회합니다.
